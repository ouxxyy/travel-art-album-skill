# 红队审查：阶段一执行方案

## Top Kill-Assumptions（排序后）

### 1. 来源可合法复用

- **Claim：**三种风格规范与翻页实现可进入可分享安装包。
- **Fails if：**风格来源或翻页库没有允许修改和再分发的许可。
- **本周证据：**固定 commit/tag，直接检查仓库许可与包元数据。
- **Kill criterion：**缺少明确许可的任何实现不得复制进安装包。
- **Cheapest test：**检查根目录许可证并保存 commit hash。结果：两项 MIT 通过；相册参考仓库无许可，隔离为思想参考。

### 2. 宿主真的能做参考图编辑

- **Claim：**宿主可逐张携带原图生成艺术化版本。
- **Fails if：**只有文本生图，或工具不能读取本地参考图。
- **本周证据：**检查工具契约，并在用户提供照片后做一张最小编辑。
- **Kill criterion：**无法把对应原图传入编辑调用时立即停止，不做文本猜图降级。
- **Cheapest test：**接口检查已通过；真实图编辑尚待素材。

### 3. 单文件在 `file://` 下确实离线可用

- **Claim：**内嵌 bundle 与资源后，画册不需要服务器或网络。
- **Fails if：**使用 ES module、fetch、外部字体/CDN 或跨源资源。
- **本周证据：**Chromium 拦截全部 HTTP(S)，从 `file://` 打开并操作。
- **Kill criterion：**出现任何外网请求或核心翻页失败就不交付。
- **Cheapest test：**四页占位原型 smoke test。

### 4. 人物辨识度能跨三种强风格保持

- **Claim：**三种风格都能在艺术材质明显的同时让熟人认得本人。
- **Fails if：**代表照片中身份、人数、面部或肢体持续漂移，三次尝试后仍不合格。
- **本周证据：**用户提供近景、双人、环境三张照片，生成 3×3 小样并逐项检查。
- **Kill criterion：**某风格在代表照片上频繁身份漂移则淘汰或降低抽象度。
- **Cheapest test：**先做九张样片，不批量。当前因无素材未执行。

## What's Well-Reasoned

样片确认与批量之间设置硬门禁、原图只读、制作清单隔离生图和画册构建、缺能力时停止而非假兼容，这些约束直接降低了成本、隐私和错误扩散风险。

## What I Couldn't Assess

没有用户照片，无法评价真实人物辨识度、横图重构、HEIC 方向以及不同风格的一致性；没有 Safari 自动化通道，无法提供其运行证据。
